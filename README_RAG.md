# Middleware + HITL lab: policy-aware refund extension

This repo keeps the original `middlewareHITLMAS.py` unchanged so the class exercise can serve as a baseline. The extension is `middlewareHITLMAS_RAG.py`.

## What changed

A new LangGraph `retrieve_policy` node runs **only for BILLING tickets** between triage and the refund agent:

```
START → sanitize_intake → triage → (BILLING?) → retrieve_policy → draft_refund_action → END
                                    ↳ other categories → END
```

It reads `refund_policy.json`, scores policy entries by keyword matches in the **redacted summary**, selects at most two passages, and provides them to the refund agent alongside the complaint. A fallback policy covers cases with no keyword match.

This is **retrieval-augmented generation using keyword search**, not vector/embedding-based semantic retrieval. For four short policies, no vector database is needed. It introduces no extra LLM call, so it should have low additional local inference overhead.

Policy IDs:
- POL-001: Duplicate charges
- POL-002: Announced subscription price changes
- POL-003: Unverified/unclear billing disputes
- POL-004: Previously refunded charges

These are **illustrative fictional business rules** for the lab, not independently verified company policy. The refund tool is simulated and only returns a confirmation string.

The extension also fixes a baseline HITL input issue: unrecognized responses no longer silently count as `edit`, and edited tool calls retain the original email and reason while changing the amount.

## Run locally (Mac)

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install langchain langgraph langchain-ollama python-dotenv typing-extensions
ollama pull qwen2.5:3b
python -m unittest -v test_policy_retrieval.py
python middlewareHITLMAS_RAG.py
```

Use `python middlewareHITLMAS.py` to run the baseline. Keep Ollama running for full agent tests. To run unit tests, Ollama is **not** needed.

## Evaluation plan for the IS 590R extension memo

Run baseline and extension on the **same model**, sample messages, and approval decisions. Use repeated runs to distinguish model variability from actual improvement. Check:
1. Did a duplicate $49.99 complaint produce a $49.99 rather than $99.98 proposal?
2. Did a previously announced subscription price change avoid an unwarranted refund?
3. Was a previously refunded charge flagged?
4. Did non-billing complaints skip the refund agent?
5. Which policy ID did the retrieval node return, and did the agent follow it?

Capture LangSmith traces and screenshots of your own runs for the evidence log. These were not generated by the code changes alone.

## Limitations

Retrieval is simple keyword matching and may miss paraphrases, so testing matters. The refund agent still receives the original message (including any PII), as in the base lab. There is no actual billing-record verification, no monetary limits, and no durable database; a human must still review each proposed refund. Do not claim the example policy is equivalent to a verified charge.
